CRITERIOS DEFINITIVOS
=====================

1. Las interfaces de entrada:
   - CrearSolicitudCreditoUseCase
   - EjecutarEvaluacionScoringUseCase
   se ubican en:
   application/port/in/

   En Clean no se conserva la carpeta application/usecase/.
   Las interfaces UseCase se tratan explícitamente como puertos de entrada.

2. Los contratos de persistencia se ubican en:
   application/port/out/
   porque son dependencias requeridas por los casos de uso.

3. La entrada REST se agrupa en:
   motor-scoring-interface-adapters/adapter/in/rest/

4. El adaptador JPA/H2 se agrupa en:
   motor-scoring-interface-adapters/adapter/out/jpa/

5. El adaptador MongoDB se agrupa en:
   motor-scoring-interface-adapters/adapter/out/mongodb/

6. MongoSequenceService se conserva explícitamente en:
   adapter/out/mongodb/sequence/MongoSequenceService.java

7. La configuración técnica de Spring, JPA y MongoDB se concentra en:
   motor-scoring-frameworks/.../framework/config/

   Aquí se ubican:
   - ApplicationBeanConfiguration
   - JpaPersistenceConfiguration
   - MongoPersistenceConfiguration

8. Los wrappers transaccionales se ubican en:
   motor-scoring-frameworks/.../framework/transaction/

9. MotorScoringApplication permanece en:
   motor-scoring-bootstrap/.../MotorScoringApplication.java

10. OnionBeanConfiguration cambia en Clean:
    - Nombre: ApplicationBeanConfiguration
    - Ruta: motor-scoring-frameworks/.../framework/config/ApplicationBeanConfiguration.java

11. La lógica del negocio no se modifica:
    - entidades
    - value objects
    - servicios de dominio
    - comandos
    - DTOs
    - servicios de aplicación
    - reglas del scoring

12. Cambiar entre H2 y MongoDB continúa afectando únicamente al adaptador
    de persistencia y a la configuración activa; no modifica la lógica de negocio.
